🔍 HTTP vs HTTPS: Man-in-the-Middle Attack Demonstration

📡 What Does an Attacker See?

When you send data over the network, an attacker performing a Man-in-the-Middle (MITM) attack can intercept the traffic. HTTP sends data in plain text (readable), while HTTPS encrypts the data (unreadable gibberish). Click any button above to see what an attacker would intercept:

🔓 HTTP Traffic (Unencrypted)

⚠️ VULNERABLE: Attacker can read everything in plain text!

Click any button above to see what an attacker would intercept

❌ Attacker sees: passwords, session tokens, personal data, API keys - EVERYTHING!

🔒 HTTPS Traffic (Encrypted)

✅ PROTECTED: Attacker only sees encrypted gibberish!

Same request but encrypted - unreadable to attackers

✅ Attacker cannot read the content - data is encrypted!

🎓 Key Takeaway:

HTTPS encrypts data in transit, protecting against eavesdropping and MITM attacks. However, HTTPS does NOT protect against application vulnerabilities like the insecure deserialization shown above. Once the encrypted data reaches the server and is decrypted, vulnerable server code can still be exploited.

Defense requires BOTH:
• HTTPS for transport security (encryption)
• Secure coding practices for application security (input validation, sanitization)
